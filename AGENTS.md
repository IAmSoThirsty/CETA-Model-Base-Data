# CETA project scope

Updated: September 6, 2026.

## Project identity

The official desktop application name is **CETA**. This project remains the
existing CETA reference, training, and native desktop application repository.
Changing its public application name does not create or select another repository.
CETA also names the existing Constitutional Epistemic Transition Algebra reference
core. Preserve that core while working on the desktop application.

## User authority and project boundaries

Apply the user's global `T:\PROJECT_ISOLATION_RULEBOOK.md`. Do not mix another
project's code, branding, paths, instructions, data, models, conversations,
evidence, or outputs into CETA without express user authorization specifying the
source, destination, and scope. Memory summaries and other conversations are
context with provenance, not authorization to import another project.

## Workflow and evidence

Verify the current root, branch, and dirty state before editing. Preserve existing
CETA work, untracked files, ignored artifacts, and accurate historical evidence.
Earlier artifact names and hashes remain historical records; do not rewrite them
as evidence for a newly named or rebuilt application. Check current source,
documentation, packaging, and new outputs for unintended project crossover.

When validation fails, record the exact failure and classify it before making a
targeted correction. The user's current explicit instructions take priority over
project assumptions. Read `docs/operations/CONTINUITY_MAP.md` when continuing this
work and record actual changes, validation, and remaining issues there. A task
summary must retain the project boundary and the scope of any user authorization.
